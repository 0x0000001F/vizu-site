# Module 2 · x86-64

Read alongside: CS:APP chapter 3 (sections 3.2–3.8) · Jorgensen, *x86-64
Assembly Language Programming with Ubuntu* (free), chapters 2, 7–9, 12–13

x86-64 is the instruction set of PCs and most servers: Intel's and AMD's
64-bit extension of the 8086 of 1978. It is a CISC design: many instructions,
of different lengths, and most of them can take a memory operand. The
programs here use NASM's syntax (Intel order: the destination first) and run
as Linux programs from `_start`, with no C library.

## 2.1 Registers: rax to r15, and their parts

**Read:** CS:APP 3.4 · Jorgensen chapter 2
**You will:** use the 16 registers and see what writing a part of one does.

There are 16 general registers of 64 bits: `rax`, `rbx`, `rcx`, `rdx`,
`rsi`, `rdi`, `rbp`, `rsp` (the stack pointer) and `r8` to `r15`. Each has
smaller parts with their own names: `eax` is the low 32 bits of `rax`, `ax`
the low 16, `al` the low 8 (and `r8d`, `r8w`, `r8b` for the new ones). The
instruction pointer `rip` plays the role of the PC.

One rule surprises everyone: **writing a 32-bit part clears the upper 32
bits**, but writing an 8- or 16-bit part keeps the rest.

```asm run arch="x86"
section .text
global _start
_start:
    mov  rax, -1        ; all 64 bits set
    mov  eax, 5         ; writing eax clears the upper half: rax = 5
    mov  rbx, -1
    mov  bl, 7          ; writing bl keeps the rest
    mov  rdi, rax       ; exit status: 5
    mov  rax, 60
    syscall
```

**Watch:**

- After `mov eax, 5`, `rax` is 5: Write back says the upper 32 bits were
  cleared.
- After `mov bl, 7`, `rbx` is −249: only the low byte changed, to 7, under
  all the ones.
- `mov rax, -1` is 7 bytes: `48` (REX.W: 64-bit), `C7` (mov with a
  number), the ModRM byte, and the number as 32 bits, sign-extended.

### Check yourself

1. What is in `rbx` after `mov bl, 7`, in hex?
   <details><summary>Answer</summary>

   `0xFFFFFFFFFFFFFF07`, which is −249 as a signed number.
   </details>

2. What does `mov ax, 1` do to the rest of `rax`?
   <details><summary>Answer</summary>

   Nothing: only the low 16 bits change. Only 32-bit writes clear the top.
   </details>

### Common mistake

Using `al` for a byte and then `rax` for the whole value, forgetting the
upper bits still hold whatever was there. Clear the register first
(`xor eax, eax`) or widen with `movzx`.

## 2.2 Arithmetic and the flags

**Read:** CS:APP 3.5, 3.6.1 · Jorgensen chapter 7
**You will:** do arithmetic and read ZF, SF, CF and OF.

`add`, `sub`, `imul`, `inc`, `dec` and `neg` work on a register or memory,
and set the **flags**: ZF (the result is zero), SF (its top bit, the sign),
CF (an unsigned carry or borrow) and OF (a signed overflow). The same bits
mean different things to signed and unsigned code; the jump chosen decides
which.

```asm run arch="x86"
section .text
global _start
_start:
    mov  rax, 7
    sub  rax, 10        ; -3: SF = 1, and CF = 1 (as unsigned, 7 < 10)
    mov  rbx, 0x7fffffffffffffff
    add  rbx, 1         ; the largest long + 1: OF = 1
    imul rcx, rax, 4    ; -12
    neg  rcx            ; 12
    mov  rdi, rcx       ; exit status: 12
    mov  rax, 60
    syscall
```

**Watch:**

- `sub rax, 10`: the flags light up in **Execute**: SF = 1 and CF = 1, OF
  = 0 (no signed overflow: −3 fits).
- `add rbx, 1` wraps to the most negative number: OF = 1, SF = 1, CF = 0.
- `mov rbx, 0x7fff…` is 10 bytes: a 64-bit number does not fit in the
  usual 32-bit field, so the instruction carries all 8 bytes.

### Check yourself

1. After `sub rax, 10` with `rax` = 7, which jump would be taken: `jl` or
   `jb`?
   <details><summary>Answer</summary>

   Both: `jl` (signed less: SF ≠ OF) and `jb` (unsigned below: CF = 1).
   With 7 and 10 they agree; with −1 and 1 they would not.
   </details>

2. Why does `inc` leave CF alone?
   <details><summary>Answer</summary>

   History: the 8086 used it in loops that add with carry. So `inc rcx`
   changes ZF, SF and OF but not CF.
   </details>

### Common mistake

Using a signed jump (`jl`, `jg`) for unsigned values, or the reverse (`jb`,
`ja`). `cmp` cannot know which you mean; the jump does.

## 2.3 Jumps and loops

**Read:** CS:APP 3.6.3–3.6.7 · Jorgensen chapter 7
**You will:** write strlen with a compare and two jumps.

A loop is a label and a jump back; an `if` is a jump over. `jmp` always
jumps; `je`, `jne`, `jl` and the others jump when their flags say so. The
target is stored as a distance from the next instruction.

```asm run arch="x86"
section .data
s       db "assembly", 0
section .text
global _start
_start:
    mov  rsi, s          ; rsi = the address of the first byte
    xor  ecx, ecx        ; count = 0
next:
    cmp  byte [rsi + rcx], 0
    je   done            ; the 0 at the end: stop
    inc  rcx
    jmp  next
done:
    mov  rdi, rcx        ; exit status: the length, 8
    mov  rax, 60
    syscall
```

**Watch:**

- `cmp byte [rsi + rcx], 0` reads memory: Execute computes `rsi + rcx`,
  Memory reads one byte (blue in `.data`), and the flags compare it with 0.
- `byte` is needed: with only a number to compare with, the assembler
  cannot know how many bytes to read.
- `je done` falls through eight times; on the 0 it jumps.

### Check yourself

1. How is the target of `jmp next` stored in its bytes?
   <details><summary>Answer</summary>

   As a distance: `E9` and a 32-bit number counted from the end of the
   `jmp` itself (negative here, since `next` is behind).
   </details>

2. Rewrite the loop so that only one jump runs per character.
   <details><summary>Answer</summary>

   Test at the bottom: `jmp` to the test once, then `inc rcx`, the test,
   and `jne` back to the `inc`. Compilers lay loops out that way.
   </details>

### Common mistake

Forgetting the size on a memory operand with a number (`cmp [rsi], 0`):
the assembler refuses, because a byte, a word, a dword and a qword are
different instructions.

## 2.4 Memory and addressing

**Read:** CS:APP 3.4.1, 3.8 · Jorgensen chapter 8
**You will:** walk an array with `[base + index*8]`, and know `lea`.

An x86-64 memory operand is `[base + index*scale + disp]`: two registers, a
scale of 1, 2, 4 or 8, and a number. That is exactly what an array needs:
`nums[i]` for 8-byte elements is `[rbx + rcx*8]`. `lea` computes such an
address without reading memory, and `[rel x]` means "x, counted from the
next instruction", which is how real programs find their data.

```asm run arch="x86"
section .data
nums    dq 3, 1, 4, 1, 5
count   equ 5
section .text
global _start
_start:
    lea  rbx, [rel nums]     ; rbx = the array's address
    xor  eax, eax            ; sum = 0
    xor  ecx, ecx            ; i = 0
add_one:
    add  rax, [rbx + rcx*8]  ; sum += nums[i]
    inc  rcx
    cmp  rcx, count
    jl   add_one
    mov  rdi, rax            ; exit status: 14
    mov  rax, 60
    syscall
```

**Watch:**

- In `.data`, the five numbers are 8 bytes each, lowest byte first.
- `add rax, [rbx + rcx*8]` reads memory and adds in one instruction: its
  Memory stage comes before Write back. On ARM64 and RISC-V that takes a
  load and an add.
- Its encoding has a SIB byte: scale 8, index `rcx`, base `rbx`.

### Check yourself

1. What address does `[rbx + rcx*8]` reach when `rcx` is 3?
   <details><summary>Answer</summary>

   `0x2000 + 24 = 0x2018`, the fourth number.
   </details>

2. What is the difference between `lea rax, [rbx + 8]` and `mov rax, [rbx
   + 8]`?
   <details><summary>Answer</summary>

   `lea` puts the address, `rbx + 8`, in `rax`; `mov` reads the 8 bytes at
   that address. Compilers also use `lea` for plain arithmetic.
   </details>

### Common mistake

Scaling by 1 for an array of 8-byte numbers: `[rbx + rcx]` walks byte by
byte, and reads pieces of two numbers at once.

## 2.5 The stack and functions

**Read:** CS:APP 3.7 · Jorgensen chapters 9 and 12
**You will:** call a function by the System V rules and build a frame.

`push` puts 8 bytes below `rsp` and moves `rsp` down; `pop` does the
reverse. `call` pushes the return address and jumps; `ret` pops it into
`rip`. Linux's **System V** calling convention says where things go: the
first six integer arguments in `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`, the
result in `rax`; a function may change those freely, but must give back
`rbx`, `rbp` and `r12`–`r15` as they were; and `rsp` is a multiple of 16 at
each `call`.

```asm run arch="x86"
section .text
global _start
_start:
    mov  rdi, 10         ; a
    mov  rsi, 20         ; b
    mov  rdx, 12         ; c
    call add3            ; pushes the return address, jumps
    mov  rdi, rax        ; exit status: 42
    mov  rax, 60
    syscall

add3:                    ; long add3(long a, long b, long c)
    push rbp             ; keep the caller's frame pointer
    mov  rbp, rsp        ; this frame starts here
    mov  rax, rdi
    add  rax, rsi
    add  rax, rdx
    pop  rbp
    ret                  ; pop the return address into rip
```

**Watch:**

- `call add3`: Memory writes the return address (`0x101a`) at `0x7ff8`,
  amber in the stack, and `rsp` becomes `0x7ff8`.
- `push rbp` adds another 8 bytes; `mov rbp, rsp` marks the frame.
- `ret`: Memory reads `0x101a` back, and PC update jumps there.

### Check yourself

1. What is at `rbp` and at `rbp + 8` inside `add3`?
   <details><summary>Answer</summary>

   At `rbp`: the caller's old `rbp` (0 here). At `rbp + 8`: the return
   address. Locals would go below `rbp`, at `rbp - 8` and down.
   </details>

2. Which registers may `add3` change without saving them?
   <details><summary>Answer</summary>

   `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`–`r11`. If it used `rbx` or
   `r12`, it would have to push and pop them.
   </details>

### Common mistake

An unbalanced `push` and `pop`. `ret` then pops the wrong 8 bytes and jumps
there; usually that is a crash, sometimes a jump into the wrong code.

## 2.6 Talking to Linux: write, read and exit

**Read:** CS:APP 8.1, 10.1–10.4 · Jorgensen chapter 13
**You will:** print a number, and read a line.

There is no `printf` here: to print 1234, a program makes the characters
itself. `div` divides `rdx:rax` (a 128-bit number) by its operand: the
quotient goes to `rax`, the remainder to `rdx`. Dividing by 10 again and
again gives the digits from the last; adding `'0'` makes each a character.

```asm run arch="x86"
section .bss
buf     resb 21
section .text
global _start
_start:
    mov  rax, 1234           ; the number to print
    lea  rsi, [rel buf + 20] ; fill buf from the end
    mov  byte [rsi], 10      ; a newline last
    mov  rbx, 10
digit:
    xor  edx, edx            ; rdx:rax is what is divided
    div  rbx                 ; rax = rax / 10, rdx = rax % 10
    add  dl, '0'             ; the digit as a character
    dec  rsi
    mov  [rsi], dl
    test rax, rax
    jnz  digit
    mov  rdx, buf + 21       ; length = the end − rsi
    sub  rdx, rsi
    mov  rax, 1              ; write(1, rsi, rdx)
    mov  rdi, 1
    syscall
    mov  rax, 60             ; exit(0)
    xor  edi, edi
    syscall
```

**Watch:**

- Each `div` shows the quotient and the remainder; the digits appear in
  `buf` from the right: `4`, `3`, `2`, `1`.
- `.bss` holds `buf`: memory that starts as zeros and takes no room in the
  program file.
- `syscall`'s Write back: `rax` gets 5 (the bytes written), and `rcx` and
  `r11` are overwritten.

`read` (number 0) works the same way in the other direction: it waits for a
line typed at the keyboard and copies it into memory.

```asm run arch="x86" input="Ada\n"
section .data
hi      db "Hi, "
section .bss
name    resb 32
section .text
global _start
_start:
    mov  rax, 0          ; read(0, name, 32)
    mov  rdi, 0
    lea  rsi, [rel name]
    mov  rdx, 32
    syscall              ; rax = how many bytes came: 4
    mov  r12, rax        ; keep it (rcx and r11 do not survive a syscall)
    mov  rax, 1          ; write(1, hi, 4)
    mov  rdi, 1
    lea  rsi, [rel hi]
    mov  rdx, 4
    syscall
    mov  rax, 1          ; write(1, name, r12)
    mov  rdi, 1
    lea  rsi, [rel name]
    mov  rdx, r12
    syscall
    mov  rax, 60
    xor  edi, edi
    syscall
```

### Check yourself

1. Why `xor edx, edx` before every `div`?
   <details><summary>Answer</summary>

   `div` divides the 128-bit `rdx:rax`. The remainder from the last round
   is still in `rdx`; left there, it becomes the high half and the result
   is wrong, or too big for `rax` (a divide error).
   </details>

2. What does `read` return when the input has ended?
   <details><summary>Answer</summary>

   0. A program reading until the end loops while `read` returns more than 0.
   </details>

### Common mistake

Keeping a value in `rcx` or `r11` across a `syscall`: the CPU writes the
return address and the flags there.

```asm run arch="x86" expect="error"
section .text
global _start
_start:
    mov  rax, 100
    xor  ebx, ebx        ; the divisor: 0
    div  rbx             ; a divide error
    mov  rax, 60
    syscall
```
